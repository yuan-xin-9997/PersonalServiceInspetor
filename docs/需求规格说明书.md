# 需求规格说明书

## 1.2 AI 接入增量需求

核心巡检状态、检查项、事件、历史、异步任务及逐项结果提供 `/api/v1` API 和外部可发现调用的 `/mcp`。管理员可授权异步只读巡检和单项开关；开关须明确确认，不开放远程命令、删除或批量修改。复用原业务服务与页面权限，凭据范围始终受用户当前权限约束。

系统配置导航下增加 AI 接入页面，复用登录、布局和权限。用户仅能管理自己的凭据，支持名称、有效期、最小 scope、一次性密钥复制、元数据分页、影响说明及确认撤销；无明文回查。密钥/令牌不得存入浏览器存储、URL、日志或构建产物。

机器请求独立 Bearer 鉴权。MCP 采用官方 SDK、HTTPS、OAuth 资源发现、公共客户端注册、S256 PKCE、授权确认、资源绑定、短期令牌和刷新轮换。自动化程序以环境注入 API Key，自动换取令牌。普通用户不能签发管理员 scope，停用、降权、撤销立即影响既有凭据和令牌。

任务持久化排队，返回任务 ID；支持状态/结果/错误查询、并发幂等、参数校验、分页、统一业务错误、合理限流和不含敏感正文的审计。重启恢复排队任务，对中断运行任务标记失败，禁止无确认自动重放。

部署保留原 HTTP 入口和线上配置，增加仅内网绑定的 HTTPS 入口；不扩展公网。备份原数据库/配置/账号，停服前安装验证依赖，等待已有任务完成后切换，失败自动回滚。完整接口和兼容范围见《AI接入说明》。浏览器与生产验收的完成状态以《测试报告》记录为准，不把协议适配当作所有客户端已实测。

## 1. 目标与范围

系统运行在 Ubuntu `192.168.0.111`，统一巡检三台服务器、个人服务内外网入口、Docker、PostgreSQL、MySQL、分析类系统日志和 Jenkins。目标是尽早发现故障、抑制偶发抖动、保留 30 天以上可查询历史，并以每日 09:00 HTML 日报交付结果。1.1 版本增加“巡检管理”页面和可视化仪表盘，巡检项开关、巡检时间、间隔和阈值可以在线维护。

## 2. 用户与权限

- 管理员：查看全部页面、手动巡检、邮件预览/测试、查看脱敏配置、维护普通用户页面权限。
- 普通用户：登录并访问获授权页面，不可手动巡检或查看系统配置。
- 健康探针：仅访问 `/health/live` 与 `/health/ready`。

用户来源是运行时 `data/password.txt`。管理页面与除健康探针外的 API 必须鉴权。

## 3. 功能需求

1. 支持 TCP、HTTP、JSON、关键字、响应时间和 TLS 检查。
2. 通过 SSH 只读采集主机、Docker 和有限大小的日志样本。
3. 通过只读查询检查 PostgreSQL/MySQL 连接、容量、连接数、长事务和锁等待。
4. 展示当前状态、最近成功、连续失败、事件、响应时间、任务与 30 天历史。
5. 过去 24 小时日志尽量按行内时间戳过滤，识别 ERROR/WARN/CRITICAL/FATAL、Traceback、timeout、connection refused、数据库错误和 HTTP 4xx/5xx。
6. WARNING 立即记录事件但不即时发信；CRITICAL 连续失败 3 次开启事件；故障和恢复即时邮件默认关闭。
7. 北京时间每日 09:00 发送 HTML 日报；其他时间不自动发送日报或其他报告类邮件，支持仅预览与测试邮件。
8. 使用 YAML 调整阈值默认值，使用环境变量/Jenkins Credentials 维护秘密。
9. 提供“巡检管理”页面，将主机、服务和接口、Docker、数据库、日志、Jenkins 和定时任务统一归入该菜单；页面本身提供巡检项开关、巡检计划和巡检参数维护。
10. 每个巡检项可单独启用或停用。停用后保留历史数据，不再执行巡检，不计入总体状态和异常统计；已有未恢复事件标记为 `CLOSED`。
11. 巡检计划支持固定间隔和每日定时两种模式，可配置间隔分钟数、每日时间点、跨天时间窗口、日报时间和启动时是否立即巡检；修改后立即重载调度。
12. 仪表盘用环形图展示状态分布、用堆叠柱状图展示 7/14/30 天趋势、用分类条形图展示各类别健康度，并用状态卡片展示每个巡检项的最新情况。
13. 巡检参数可配置检查超时、连续失败阈值、响应时间预警、TLS 预警/严重天数、磁盘和 Inode 阈值、日志最大读取字节数。运行时配置保存在 SQLite，代码发布不覆盖。

## 4. 非功能需求

- 单次日志读取默认上限 5 MiB，不把大量原始日志写入邮件。
- 检查器仅执行读取；不重启、不清理、不修改数据库。
- SQLite、配置、报告和日志在版本发布间持久化。
- 巡检开关、调度和阈值等运行时配置保存在 SQLite，Jenkins 增量部署不得覆盖。
- 部署失败必须回滚到上一个健康版本；保留当前版本和两个历史版本。
- 页面状态图表不依赖外部 CDN 或重型前端组件，离线内网可用。
- 项目使用 Python 3.12，Ruff 和 pytest 通过后才允许部署。

## 5. 验收标准

- 24 个自动化测试全部通过，Python 3.12 生产 virtualenv 可创建并启动。
- `/health/live`、`/health/ready` 返回 200。
- 能执行真实巡检并保存每项结果。
- 能生成 HTML 日报预览；SMTP 配置后能发测试邮件。
- 通过构造连续故障和恢复验证去重、恢复事件与默认不发送即时邮件。
- 能在“巡检管理”中启用/停用巡检项，停用项不参与后续执行和总体统计。
- 能在页面保存固定间隔或每日定时计划，APScheduler 下次执行时间随之更新。
- 仪表盘能展示状态分布、趋势、分类健康度和每个巡检项的最新状态。
- Jenkins 任务从 SCM 拉取、构建、部署、健康验证成功。
