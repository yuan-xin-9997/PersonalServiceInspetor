# 巡检项清单

初始配置以 2026-08-13 的 `PersonalInformationMarkdownFile` 提交 `fb3f8425198db137c8de135e6a50a3c502d90b09` 为依据。

> 1.1 版本起，管理员可以在“巡检管理”页面单独启用或停用下列巡检项，并调整巡检间隔、每日时间点、时间窗口、日报时间和阈值。开关与运行时参数保存在共享 SQLite 中，升级不会覆盖。停用项保留历史，但不再执行，也不计入总体状态和异常统计。

## 主机

- `192.168.0.100` NAS：基础 TCP 在线；完整指标待 NAS SSH 凭据。
- `192.168.0.111` Ubuntu 24.04：SSH 主机指标、Docker、日志。
- `192.168.0.110` CentOS 7.9：SSH 主机指标和 MySQL。

## 服务

内网与对应公网入口覆盖：个人博客、Hermes、特朗普贴文分析、Jenkins、Nginx Dashboard、Jellyfin、Clash Dashboard、RSSHub、Kavita、Portainer、FreshRSS、Vaultwarden、Gitea、公开人物行程追踪、Trilium、官员履历分析、青龙、信息智能分析、百度网盘分享管理、翻译、OCR、政策分析；WebFetch 覆盖内网 ready 接口。

标准健康接口存在时使用 `/health/live`、`/health/ready` 或 `/health`；未提供标准接口的项目使用首页允许状态码，属于“基础检查”。HTTPS 检查同时读取 TLS 剩余天数。

## 数据库与平台

- PostgreSQL `192.168.0.100:15432`：连通、当前库容量、连接数、超过 10 分钟事务、锁等待。
- MySQL `192.168.0.110:3306`：连通、当前库容量、连接数。
- Ubuntu/NAS Docker：容器状态与 `docker stats` 快照；NAS 深度采集待 SSH 凭据。
- Jenkins：任务结果、最近构建、耗时、最近成功时间。

## 日志

覆盖 `/opt/*AnalysisSystem/logs/*.log`、`/opt/*TrackingSystem/logs/*.log`、`/opt/BaiduPanShareManagement/logs/*.log`。默认只读取最近修改文件合并后的最后 5 MiB。Docker stdout/stderr 可由 `docker_ssh` 状态检查扩展；systemd 关键日志由主机 SSH 检查读取最近 24 小时摘要。

## 当前限制

- 无 NAS SSH 凭据时不能列出 NAS 容器及主机 CPU/内存/磁盘细项。
- 未配置应用登录/API Token 的服务仅做公开健康或首页基础检查。
- 备份最近时间因尚无统一备份目录规范，初始配置未自动判断。
- 日志 7 天基线数据需积累至少 7 天后才有统计意义。

## 首次实测发现

- 正常：三台主机基础在线、Ubuntu/CentOS SSH 指标、PostgreSQL、全部可达内网健康入口等共 24 项。
- 警告：公网入口主要因响应超过 3 秒阈值；Jenkins 保留一次失败构建；分析日志错误量高于尚未成熟的基线。
- 严重：博客、Portainer、Hermes、CentOS MySQL 和 Ubuntu 异常容器，均保留真实状态供处理。
- 未知：NAS Docker 深度采集缺少 NAS SSH 凭据。
