# 运维手册

## 日常检查

1. 管理页面确认总体状态、当前事件和下一次日报时间。
2. Jenkins 确认最近构建为 SUCCESS。
3. `docker compose ps` 确认容器 healthy。
4. 关注 data 和 logs 所在文件系统，不直接删除 SQLite 文件。

## 常用操作

```bash
cd /opt/personal-system-inspector/current
docker compose -p personal-system-inspector ps
docker compose -p personal-system-inspector logs --tail=200 inspector
docker compose -p personal-system-inspector restart inspector
```

重启属于人工运维操作，巡检程序本身不会自动执行。

## 修改检查项

编辑 `/opt/personal-system-inspector/shared/config/checks.yaml`，先备份并做 YAML 语法检查，再重启容器。ID 不可重复。业务健康检查优先于首页检查；已有业务接口时增加 JSON 字段和更新时间断言。

## 用户与权限

编辑共享 `data/password.txt`，格式为 `username:password:admin|user`。避免冒号出现在用户名或密码中。应用重启后同步新用户；普通用户权限由管理员页面/API 修改。删除一行不会自动删除数据库权限记录，但该账号立即无法认证。

## 邮件

配置 `.env` 中 SMTP 后重启服务，先访问日报预览，再用测试邮件接口验证。邮件失败写入任务中心，不会阻断巡检持久化。

## SQLite 备份

在容器运行时优先用 SQLite 在线备份命令，或短暂停止容器后复制 `shared/data/inspector.sqlite3`。恢复前保留当前文件，确认属主和权限后启动并检查 ready。

## 故障定位顺序

1. 外网失败、内网正常：检查 Cloudflare Tunnel/Nginx Proxy Manager、DNS 和 TLS。
2. 内外网均失败：检查应用进程/容器、端口和本机日志。
3. UNKNOWN：检查对应 SSH/数据库/Jenkins 环境变量与网络 ACL。
4. 日志无增长：确认路径、轮转规则、权限和应用是否真的应产生日志。
5. 数据库失败：仅执行连接和只读查询，人工检查服务进程、磁盘、认证和最大连接数。
