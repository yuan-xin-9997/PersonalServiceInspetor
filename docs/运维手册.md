# 运维手册

## 日常检查

1. 管理页面确认总体状态、当前事件和下一次日报时间。
2. Jenkins 确认最近构建为 SUCCESS。
3. `systemctl is-active personal-system-inspector` 应返回 `active`。
4. 关注共享 data 和 logs 所在文件系统，不直接删除 SQLite 文件。

## 常用操作

```bash
systemctl status personal-system-inspector --no-pager
sudo systemctl restart personal-system-inspector
sudo systemctl stop personal-system-inspector
sudo systemctl start personal-system-inspector
journalctl -u personal-system-inspector -f
curl --fail http://127.0.0.1:31880/health/ready
```

重启属于人工运维操作，巡检程序本身不会自动重启自己或被巡检服务。

## 修改检查项

非敏感巡检项在仓库 `config/checks.yaml` 中维护并通过 Jenkins 发布。紧急修改 `/opt/personal-system-inspector/shared/config/checks.yaml` 后需重启服务，但下次发布会恢复为仓库版本。ID 不可重复；业务健康检查优先于首页检查。

`/opt/personal-system-inspector/shared/config/app.json` 是部署后运维配置，增量发布不会覆盖。

## 用户与权限

编辑共享 `data/password.txt`，格式为 `username:password:admin|user`。避免冒号出现在用户名或密码中。应用重启后同步新用户；普通用户权限由管理员页面/API 修改。

## 邮件

SMTP 由 Jenkins Credential 注入共享 `.env`。修改凭据后重新部署或重启服务，再访问日报预览并用测试邮件接口验证。邮件失败写入任务中心，不阻断巡检持久化。

## SQLite 备份

优先使用 SQLite 在线备份命令；需要复制数据库文件时短暂停止 systemd 服务。恢复前保留当前文件，并确保 data/logs 属主为 `inspector:inspector`。

## 发布目录

```bash
readlink -f /opt/personal-system-inspector/current
find /opt/personal-system-inspector/releases -mindepth 1 -maxdepth 1 -type d -printf '%T@ %p\n' | sort -nr
```

正常情况下最多存在当前版本和两个历史版本。不要删除 `current` 指向的目录。

## 故障定位顺序

1. 服务自身不可访问：查看 `systemctl status` 和 `journalctl`，检查 31880 端口、共享目录权限和 virtualenv。
2. 外网失败、内网正常：检查 Cloudflare Tunnel/Nginx Proxy Manager、DNS 和 TLS。
3. 内外网均失败：检查目标应用进程/容器、端口和日志。
4. UNKNOWN：检查对应 SSH/数据库/Jenkins 环境变量与网络 ACL。
5. 数据库失败：巡检只执行连接和只读查询，由人工检查服务、磁盘、认证和最大连接数。
