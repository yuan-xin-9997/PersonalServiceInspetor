# 安全说明

## AI 接入安全增量

版本化 API 与 MCP 使用独立机器身份；Cookie 不能代替机器 Bearer，普通 API Key 不能直接调用 MCP。OAuth 使用公共客户端注册、S256 PKCE、resource 绑定、最长 15 分钟 access_token 和轮换 refresh_token；用户可在 AI 接入页撤销。所有访问实时与所属用户当前角色/页面权限相交。凭据管理仅本人，写操作校验 CSRF，完整密钥仅创建时返回一次，数据库仅保存随机秘密摘要。

AI API/MCP 与凭据写操作审计不含正文、密钥、密码或令牌；生产关闭 Uvicorn 请求访问日志，校验错误不回显原始输入。机器请求限流按来源 IP 与凭据摘要双重计数。保留原 HTTP 网页入口，生产机器调用请走内网 HTTPS 并校验内部 CA；不改变公网映射。旧全局 RUN_API_TOKEN 必须额外绑定 RUN_API_USERNAME 且所属用户当前仍为管理员。完整威胁边界、权限表、迁移和客户端兼容限制见《AI接入说明》。

## 秘密管理

- Git 只保存 `.env.example` 的变量名；`.env`、`data/password.txt`、SQLite 和报告不提交。
- Jenkins Credentials 在绑定阶段注入，流水线使用 `set +x`，不输出变量值。
- 发布目录和 virtualenv 不包含秘密；`.env` 位于共享目录、权限 `0600`，由 systemd 在降权前读取。
- 生产进程使用无登录 shell 的 `inspector` 系统用户，并启用 `NoNewPrivileges`、`ProtectSystem` 和最小可写目录。
- 容器入口仅以 root 初始化持久化卷属主，随后立即通过 `setpriv` 降权为 `inspector` 运行 Uvicorn。
- 邮件、应用日志和检查结果在入库前对 password、token、API key、Cookie、Authorization 和数据库连接串脱敏。

## 访问控制

- 健康探针公开且不包含配置与巡检细节。
- 管理页/API 使用签名、SameSite=Strict 的会话 Cookie。
- 手动巡检只允许管理员或长随机 Bearer Token。
- 系统配置页面过滤敏感字段，只展示非敏感检查目标和阈值。
- “巡检管理”写接口仅管理员可用；普通用户只能读取调度、阈值和检查状态。
- 巡检开关、调度和阈值存储在 SQLite，不包含任何密码或 Token；秘密仍只来自环境变量/Jenkins Credentials。
- 公网发布时应由反向代理启用 HTTPS，并把 `session_cookie_secure` 改为 `true`。

## 只读原则

- SSH 命令只包括 uptime、free、df、journalctl、docker ps/stats 和有上限的日志读取。
- PostgreSQL/MySQL 事务设置为只读，只执行 SHOW/SELECT。
- 巡检系统不删除日志、不清盘、不重启业务、不修改数据库、不执行自动修复。

## 已知风险

- `password.txt` 兼容项目规范，因此是明文凭据文件；必须限制为服务账号可读，建议后续迁移到密码哈希格式。
- Paramiko 首次连接目前接受新主机密钥，适合受控内网；更严格环境应预置 known_hosts 并拒绝未知密钥。
- CentOS 7 已停止常规安全支持，建议限制网络访问并规划升级。
