# 系统设计说明书

## 1. 组件

- `config.py`：解析 `app.json` 与 `checks.yaml`，校验唯一 ID，按 `*_env` 延迟读取秘密。
- `checkers.py`：异步调度 TCP/HTTP；阻塞 SSH/TLS/数据库操作放入工作线程；统一返回 `CheckResult`。
- `engine.py`：并发执行、持久化、状态去抖、事件开启/关闭和通知去重。
- `database.py`：SQLAlchemy 模型与事务边界。
- `mailer.py`：日报 HTML 邮件、可配置的故障/恢复通知及预览。
- `scheduler.py`：15 分钟周期巡检和北京时间 09:00 日报。
- `main.py`：FastAPI、会话认证、RBAC、健康检查和 Vue 管理页面。

## 2. 数据模型

- `check_results`：不可变的每次检查记录与指标 JSON。
- `check_states`：每个检查项当前状态、连续失败、最近成功和活动事件。
- `incidents`：事件开始、最后发生、恢复、失败次数与通知时间。
- `task_runs`：巡检和日报任务执行记录。
- `user_permissions`：用户角色与可见页面。

SQLite 适合当前单实例、低写入频率。容器仅运行一个 Uvicorn 进程，避免 APScheduler 重复执行。

## 3. 状态机

```text
OK --CRITICAL 第 1/2 次--> 记录失败
   --CRITICAL 第 3 次----> OPEN 事件
OPEN --继续失败---------> 更新次数
OPEN --OK---------------> RECOVERED
WARNING --发生----------> OPEN 事件 + 日报展示，不即时发信
任意 --UNKNOWN----------> 保持可见，不因缺少可选凭据告警
```

WARNING 作为已经满足的阈值异常立即开事件但不触发即时邮件。CRITICAL 使用每项或全局 `failure_threshold`；故障和恢复即时邮件由 `email.send_incident_notifications` 控制，默认关闭，当前生产策略只允许 09:00 日报自动发信。

## 4. 日志策略

SSH 端先按文件更新时间筛选最近 24 小时文件，再合并尾部并限制总量。应用端识别常见 ISO/斜杠时间戳，能识别时间戳时排除窗口外行；不能识别时作为受限样本统计。相似错误把数字归一化后聚类，仅保留前 5 类摘要。敏感字段先脱敏再入库和渲染。

## 5. 部署与回滚

Jenkins 以 `BUILD_NUMBER-SHA` 创建发布目录，并在每个发布目录中创建独立 Python 3.12 `.venv`。`shared/` 保存 data、logs、config 和 `.env`；发布目录保存代码、virtualenv、提交号及共享目录符号链接。`app.json` 首次创建后不覆盖，`checks.yaml` 随代码版本更新。

发布环境安装完成后才进入切换阶段：切换 `current`、由 systemd 重启 Uvicorn 并检查 live/ready。健康失败时重新指向 `PREVIOUS_RELEASE` 并重启。清理逻辑始终跳过 `current`，保留当前版本和两个历史版本。
