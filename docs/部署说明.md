# 部署说明

## 1. 服务器准备

目标路径 `/opt/personal-system-inspector`，端口 `31880`。部署前执行：

Jenkins 用户不加入 `docker` 组。流水线通过 `personal-inspector-ubuntu-ssh` 凭据和已安装的 `sshpass`，SSH 到 `yuanxin@127.0.0.1` 执行 Docker 构建与部署，从而避免给 Jenkins 进程永久 root 等价权限。`yuanxin` 已可写 `/opt` 并访问 Docker。端口必须用 `ss -lnt` 再确认未占用。

## 2. Jenkins Credentials

全局域下维护：

| ID | 类型 | 用途 |
|---|---|---|
| `truthanalysis-github-ssh` | SSH Username with private key | GitHub SCM |
| `personal-inspector-app-secret` | Secret text | 会话签名，至少 32 字符 |
| `personal-inspector-admin-password` | Secret text | 首次管理员密码 |
| `personal-inspector-run-token` | Secret text | 手动巡检 Bearer Token |
| `personal-inspector-ubuntu-ssh` | Username with password | Ubuntu 只读采集与回环部署 |
| `personal-inspector-centos-ssh` | Username with password | CentOS 只读采集 |
| `personal-inspector-postgres` | Username with password | PostgreSQL 只读检查 |
| `personal-inspector-mysql` | Username with password | MySQL 只读检查 |
| `personal-inspector-jenkins-api` | Username with password | Jenkins 只读 API |
| `personal-inspector-smtp-env` | Secret text | Base64 编码的 SMTP 环境变量载荷 |

NAS SSH 与 SMTP 尚未取得时不阻塞首次部署。部署后在 `/opt/personal-system-inspector/shared/.env` 通过安全终端补充 `NAS_SSH_*` 和 `SMTP_*`；文件权限保持 `0600`，不要输出内容到控制台。

## 3. Jenkins 任务

- 名称：`personal-system-inspector`
- 类型：Pipeline
- Definition：Pipeline script from SCM
- SCM：Git
- Repository URL：`git@github.com:yuan-xin-9997/PersonalServiceInspetor.git`
- Credentials：`truthanalysis-github-ssh`
- Branch：`*/main`
- Script Path：`src/JenkinsConfig/Jenkinsfile`
- Lightweight checkout：启用
- Poll SCM：由 Jenkinsfile 设置为每 30 分钟

## 4. 部署验证

```bash
curl --fail http://127.0.0.1:31880/health/live
curl --fail http://127.0.0.1:31880/health/ready
docker inspect --format '{{.State.Health.Status}}' personal-system-inspector
```

首次登录使用 Jenkins Credential 中的管理员初始密码。运行时 `data/password.txt` 已存在时，修改 Credential 不会重置密码。

## 5. 回滚

流水线失败会自动回滚。人工回滚：

```bash
cd /opt/personal-system-inspector
ls -1dt releases/*
ln -sfn /opt/personal-system-inspector/releases/<目标版本> current
cd current
docker compose -p personal-system-inspector up -d --remove-orphans
curl --fail http://127.0.0.1:31880/health/ready
```
