# 部署说明

## 1. 运行架构

生产环境使用 Python 3.12 virtualenv + systemd，不使用 Docker 运行本项目。目标目录 `/opt/personal-system-inspector`，监听端口 `31880`。

```text
/opt/personal-system-inspector/
├── current -> releases/<BUILD_NUMBER>-<SHA>
├── releases/
│   └── <BUILD_NUMBER>-<SHA>/
│       ├── .venv/
│       ├── src/
│       ├── pyproject.toml
│       ├── version.env
│       └── data/logs/config -> shared 对应目录
└── shared/
    ├── data/
    ├── logs/
    ├── config/
    └── .env
```

每个发布版本拥有独立 `.venv`，避免依赖变化破坏旧版本回滚。`inspector` 无登录 shell 系统用户运行 Uvicorn，Jenkins 通过 `yuanxin@127.0.0.1` 执行发布。服务器需要 Python 3.12、`python3.12-venv`、systemd、curl、sshpass，且 `yuanxin` 具有受控 sudo 权限。

## 2. Jenkins Credentials

全局域下维护：

| ID | 类型 | 用途 |
|---|---|---|
| `truthanalysis-github-ssh` | SSH Username with private key | GitHub SCM |
| `personal-inspector-app-secret` | Secret text | 会话签名，至少 32 字符 |
| `personal-inspector-admin-password` | Secret text | 首次管理员密码 |
| `personal-inspector-run-token` | Secret text | 手动巡检 Bearer Token |
| `personal-inspector-ubuntu-ssh` | Username with password | Ubuntu 只读采集与回环部署 |
| `personal-inspector-centos-ssh` | Username with password | CentOS 只读采集 |
| `personal-inspector-postgres` | Username with password | PostgreSQL 只读检查 |
| `personal-inspector-mysql` | Username with password | MySQL 只读检查 |
| `personal-inspector-jenkins-api` | Username with password | Jenkins 只读 API |
| `personal-inspector-smtp-env` | Secret text | Base64 编码的 SMTP 环境变量载荷 |

秘密写入共享 `.env`，权限保持 `0600`，不进入发布目录、Git 仓库或 Jenkins 控制台。systemd 以 root 读取 EnvironmentFile 后再降权为 `inspector`。

## 3. Jenkins 流程

- 任务：`personal-system-inspector`
- SCM：`git@github.com:yuan-xin-9997/PersonalServiceInspetor.git`
- 分支：`*/main`
- Script Path：`src/JenkinsConfig/Jenkinsfile`
- Poll SCM：每 30 分钟

流水线依次创建测试 virtualenv、安装开发依赖、运行 Ruff/pytest、检查 Python 字节码和发布脚本语法，然后创建版本化生产 virtualenv。生产环境准备完成后才切换 `current` 并重启 systemd。

增量部署保留 `shared/config/app.json` 的运维修改；`checks.yaml` 随代码版本更新。Docker 到 systemd 的首次迁移已经完成，后续部署和回滚均只使用原生 Python virtualenv。

## 4. systemd

```bash
sudo systemctl status personal-system-inspector
sudo systemctl restart personal-system-inspector
journalctl -u personal-system-inspector -n 200 --no-pager
curl --fail http://127.0.0.1:31880/health/live
curl --fail http://127.0.0.1:31880/health/ready
```

服务启用 `Restart=on-failure`、`NoNewPrivileges`、`ProtectSystem=strict`，仅共享 data 和 logs 可写。只能运行一个 Uvicorn 进程，以免 APScheduler 重复调度。

## 5. 版本保留与回滚

发布成功后只保留：

- 当前线上版本 1 个。
- 历史回滚版本 2 个。

人工回滚：

```bash
cd /opt/personal-system-inspector
find releases -mindepth 1 -maxdepth 1 -type d -printf '%T@ %p\n' | sort -nr
sudo systemctl stop personal-system-inspector
ln -sfn /opt/personal-system-inspector/releases/<目标版本> current
sudo systemctl start personal-system-inspector
curl --fail http://127.0.0.1:31880/health/ready
```

切换前确认目标目录包含 `.venv/bin/uvicorn`。流水线部署失败会自动执行同等回滚并验证 ready。
